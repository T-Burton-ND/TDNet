# Scientific 120-cell hyperparameter sensitivity study (historical inputs aligned)

This is the historical tuning-sensitivity study for F0–F19 × M1/M2/M3/M4/M5/M10. The [configuration](../../../../configs/experiments/scientific_120_hps_v1.yaml), [candidate manifest](candidate_tasks.jsonl), [plan receipt](plan.json), and [input audit](input_audit.json) define the proposed search. The materialized input matrices and run receipts live under `/groups/bsavoie2/tburton2/TDNet/scientific_120_hps_v1/`. Consult that path for launch and result status.

## Design

- Each of the 120 fingerprint × architecture cells receives 100 unique random hyperparameter sets. The same 100 architecture-specific settings are reused across all 20 fingerprints, so comparisons are paired within architecture. This is 12,000 candidate evaluations × five rolling-origin folds = **60,000 planned fits**. An incumbent-settings control would add 600 fits after its provenance is bound.
- The five test seasons are 2021–2025. For each test year, model fitting and representation fitting use 2013 through two seasons before the test; the immediately preceding season is the inner validation and calibration slice. The target is the home-team margin. Every architecture uses the same fit years, and no test-year outcome enters preprocessing, early stopping, calibration, or selection before that candidate's test prediction.
- Primary selection is lowest equal-weight mean five-fold margin MAE, then lower fold standard deviation, then lower trial ID. This gives each season equal influence despite different game counts. Preserve all failed trials and their reasons. Retain the original per-cell settings as a separate control; do not silently count them among the 100 random candidates.
- The random-search space comes from the existing scientific HPS config, with the probability-only margin-temperature parameter removed and M10 neighbor count broadened to 1–150 so 100 distinct margin-relevant configurations exist. The study keeps F18/F19 representation choices fixed. Their prior representation search is part of their historical tuning advantage; the present study equalizes only **additional** hyperparameter opportunity.
- CPU only, one thread per fit, at most ten concurrent tasks for this study. The user's hard ceilings for this work are 25 simultaneous tasks and two CPU cores per task; unrelated cluster jobs do not count. Set `CUDA_VISIBLE_DEVICES=''`, `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, and `OPENBLAS_NUM_THREADS=1` in the worker. The M5 PyTorch model is CPU-first; reject a GPU backend in the worker receipt.

## Required source gate before any fit

The original [audit](input_audit.json) recorded `blocked_before_fit` before historical matrix materialization. The aligned target ledger contains 7,358 FBS games from 2013–2025. F0–F8 are regenerated from the canonical archived team-state matrix using the original feature ladders and unit matchup builder. F9–F17 come from the staged next-generation matrix loader; F18/F19 come from the broad source with their previously selected representation held fixed. All tier matrices share the same game IDs, home/away identity, kickoff, season, and newer authoritative margin target. The old F0–F8 target field disagrees on ten games, so its values are never used for model fitting or scoring; their IDs are retained in the tier receipts.

The [materializer](../../../../scripts/publication/materialize_scientific_120_hps.py) and [preflight](../../../../scripts/publication/verify_scientific_120_hps_inputs.py) verify common game identity, season, margin, cohort ordering, observed source dates before target dates, and source game distinct from target game. Missing old-source dates occur only in synthetic preseason week-zero states. Representation transforms are fitted afresh inside each training fold. Source and matrix hashes, feature names, and market timing labels are retained in the receipts. Archived market quote timestamps remain unverified for F7/F8/F17/F19, so those cells and the common ATS secondary metric are retrospective research only. No 2026 outcome is used in this search.

The five-fold search is a **development** selector, not an unbiased generalization estimate. Report its MAE curve as tuning sensitivity. A later untouched, frozen forecast cohort is needed to claim tuned-versus-incumbent improvement. Brier, winner accuracy, and ATS are secondary. Probability calibration is fit on the immediately preceding validation season only. ATS uses the F17 archived home spread for the same game across all cells and excludes pushes. Separate market-aware and market-free interpretations. Report season-paired differences and uncertainty, rank changes, and a best-score-versus-budget trace at 1/5/10/25/50/100 candidates. Do not call proximity to Vegas an irreducible-error bound.

## Metrics-only output contract

The [worker](../../../../scripts/publication/run_scientific_120_hps_task.py) writes one JSON status receipt and five fold-metric rows per candidate. The [finalizer](../../../../scripts/publication/finalize_scientific_120_hps.py) writes `fold_metrics.csv`, `candidate_status.csv`, and `selected_configs.json` after all 12,000 candidates complete. The selected-config file retains the exact search parameters, seed, source matrix path and SHA256, feature list, base config, and F18/F19 representation receipt hash, sufficient to retrain and retain the top configuration per cell. No model checkpoints, serialized preprocessors, or prediction rows are retained. M5 emits a separate numeric loss-history CSV per candidate.

For M5, save `epoch_history.csv` with `fingerprint,architecture,trial_id,test_season,epoch,train_loss,validation_loss` and optionally learning rate. Inner validation data must precede the outer test year. For M1/M2/M10 there is no optimizer epoch; M3/M4 estimator stages are architecture-specific and not directly comparable. The common all-model loss view is **validation MAE versus number of configurations tried**, with a mean line and five-fold interquartile band for each of the 120 cells. The separate M5 plot uses the one MAE-selected configuration per cell and shows average epoch training/validation loss with a five-fold interquartile band; it records the active-fold count because early stopping changes the denominator. Averaging raw losses across M5 configurations would mix Huber, MSE, and MAE units, so it is forbidden. Do not label the search-progress plot an epoch curve.

The prepared [plotter](../../../../scripts/publication/plot_scientific_120_hps_curves.py) accepts a complete fold-metric CSV and optional M5 epoch-history CSV, and writes six 20-panel search-progress figures plus the M5 epoch panel and their numeric summary CSVs. It refuses incomplete fold metrics.

## Reproduce the preparation

```bash
python3 scripts/publication/prepare_scientific_120_hps.py
python3 scripts/publication/audit_scientific_120_hps_inputs.py
```

After materialization, run `verify_scientific_120_hps_inputs.py`, freeze a committed code snapshot with `freeze_scientific_120_hps.sh`, run five representative one-core CPU smoke candidates through `scientific_120_hps_task.sge` with `HPS_SMOKE=1`, and run `accept_scientific_120_hps_smoke.py`. Then `submit_scientific_120_hps.sh --submit` checks all receipts and running HPS tasks before queuing the 12,000-task array at `-tc 10 -pe smp 1`. The snapshot protects long-running array tasks from subsequent workspace edits. The historical input audit is a structural gate, not a leakage-free prospective proof.
