# TDNet Master Plan Source

The dated master plan records TDNet’s fingerprint-engineering and publication-design history, but parts of its July 2026 protocol language are superseded by newer sources.

## Contribution

The 2,246-line document (line count in this checkout) preserves the study motivation, feature-family rationale, model-complexity questions, temporal validation principles, freeze methodology, and implementation history. Its status ledger is dated 2026-07-29, and its section titled “Active 2026 publication protocol” is dated 2026-07-26.

## Specific claims and source-status caveat

The master plan correctly provides research-design context: feature and model complexity should be varied independently; evaluation should use temporal/grouped splits; game-level finalist predictions should be retained; and publication outputs should be reproducible from tables.

However, the dated active-protocol section is not the current authority for live 2026 roster and tier claims. It says KNN is comparative-only and refers to older F0–F7 or market-exclusion plans. The newer README and `configs/publication/confirmatory_protocol.yaml` define six architectures including M10 KNN across F0–F8, with F0–F6 as the market-free eligible set; the README also documents KNN participation in the corrected-F6 weekly poll. Use [Confirmatory Protocol Source](Source-Confirmatory-Protocol) for current rules and retain this file as historical planning evidence.
