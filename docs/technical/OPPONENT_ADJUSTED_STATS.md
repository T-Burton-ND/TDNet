TDNet / Gridiron Analytics Research Note
Opponent-Adjusted Statistics: Top Method Families, Original Papers, and Fingerprint Use
Date: 2026-05-27

Purpose
-------
This note summarizes the 5 most useful/common families of opponent-adjusted statistics for a TDNet-style college football fingerprint pipeline. The focus is not just "ranking teams," but building leakage-safe team-week fingerprints where every feature for week w only uses games available before week w.

The short recommendation for TDNet:
1. Build v1 around per-game residualized statistics and rolling aggregates.
2. Build v2 around joint offense/defense ridge models by feature family.
3. Keep Elo/Bradley-Terry/Colley-style ratings as strength-of-schedule and record-context features, not as replacements for stat fingerprints.
4. Use graph/eigenvector methods as a bridge toward v3 graph fingerprints.
5. Use dynamic Bayesian/state-space ideas as the principled target for v2/v4 time-dependent fingerprints.

Important distinction
---------------------
"Opponent adjustment" can mean several related but different things:

- Outcome-strength adjustment:
  How strong is a team after accounting for whom it beat/lost to?
  Examples: Elo, Bradley-Terry, Colley, Massey/SRS.

- Margin adjustment:
  How many points better/worse is a team after accounting for opponent and venue?
  Examples: Harville/Massey/SRS linear models.

- Unit/stat adjustment:
  How strong is an offense/defense after accounting for the defenses/offenses faced?
  Examples: adjusted offensive efficiency, adjusted defensive efficiency, adjusted PPA, ridge offense-defense models.

- Possession/play/player adjustment:
  How much did a unit/player/context contribute after controlling for opponents/teammates?
  Examples: adjusted plus-minus, regularized adjusted plus-minus.

- Time-dependent adjustment:
  How strong is a team now, after accounting for schedule and the fact that teams change over time?
  Examples: dynamic Elo/Glicko, Bayesian state-space models, dynamic attack-defense models.

For TDNet fingerprints, the best target is not a single rating. The best target is a set of leakage-safe adjusted game contributions that can be rolled into team-week feature states.

================================================================================
METHOD 1: Linear-model / least-squares schedule adjustment
================================================================================

Common names
------------
- Simple Rating System (SRS)-style adjustment
- Massey method
- Least-squares ratings
- Linear residualization with opponent fixed effects
- Margin-based strength-of-schedule correction

Original / early papers
-----------------------
- David A. Harville (1977), "The Use of Linear-Model Methodology to Rate High School or College Football Teams," Journal of the American Statistical Association.
  This is one of the clean early football-specific papers applying linear models to point spreads/margins with team effects and home-field effects.

- David A. Harville (1980), "Predictions for National Football League Games Via Linear-Model Methodology," Journal of the American Statistical Association.
  Follow-up NFL-focused prediction paper.

- Kenneth Massey (1997), "Statistical Models Applied to the Rating of Sports Teams."
  Massey's least-squares rating thesis is the canonical college-football ranking implementation. The key assumption is that expected margin is proportional to the difference between the teams' ratings.

Core idea
---------
A game margin or team-game statistic is noisy because it is generated by both the team and the opponent. Linear adjustment estimates latent team effects so that each game result is interpreted relative to opponent strength.

For margin:
    margin_home_game = home_team_rating - away_team_rating + home_field + error

For a team-game stat:
    stat_team_game = team_attack_or_unit_effect + opponent_allowed_effect + venue_effect + error

Or, for a direct residualized feature:
    observed_stat = expected_stat_given_opponent_context + residual

The residual is the "opponent-adjusted game contribution." A raw 7.5 yards/play against Georgia should not mean the same thing as 7.5 yards/play against an FCS defense. Residualization converts that into "better/worse than expected against this opponent."

Implementation pattern
----------------------
Input table:
- one row per team-game or one row per game split into home/away rows
- team_id
- opponent_id
- season
- week
- home/away/neutral
- raw stat to adjust, e.g. PPA, success rate, explosive rate, yards/play, points/drive, havoc rate, EPA-like metric

Leakage-safe weekly loop:
1. For target season-week w, construct the training set using only games with date/week < target game date/week.
2. Fit a linear model:
       y = intercept + team_effect + opponent_effect + home_effect + optional season/week controls
3. Generate expected value for each past game.
4. Compute adjusted game contribution:
       adjusted_contribution = observed_y - expected_y_without_team_effect
   or:
       adjusted_contribution = observed_y - expected_opponent_context
5. Roll adjusted_contribution into team-week fingerprints:
       mean_adjusted_last_3
       mean_adjusted_to_date
       exponentially_weighted_adjusted_to_date
       adjusted_trend_slope
       adjusted_std_to_date
       adjusted_home_split / adjusted_away_split if sample size allows
6. Persist the game-level adjusted table so later fingerprint generations can reuse it.

Recommended TDNet implementation
--------------------------------
Use this as the easiest v1.

For each important raw feature family:
- offense PPA
- defense PPA allowed
- rushing/passing success rate
- explosiveness
- havoc/sacks/TFL
- finishing drives
- points per drive
- turnover-independent efficiency if available

Build an "OA-v1 residual table":
- keys_game_id
- season
- week
- team
- opponent
- stat_name
- observed_value
- expected_context_value
- adjusted_residual
- model_version
- fit_cutoff_week
- min_games_filter_used

Then build the fingerprint from adjusted_residual, not from raw observed_value alone.

Why this is good for fingerprints
---------------------------------
- Easy to explain.
- Easy to unit test.
- Strong baseline for a paper.
- Works directly on your current team-week fingerprint architecture.
- Can be used for every numeric team-game metric.
- Creates residual features that SHAP/permutation importance can evaluate.
- Lets you compare v0 raw fingerprints vs v1 opponent-adjusted fingerprints cleanly.

Main weaknesses
---------------
- Early season estimates are unstable.
- A pure fixed-effect model can overfit if sample size is small.
- It usually treats all past games equally unless you add recency weights.
- It can double-adjust if you feed already-opponent-adjusted CFBD metrics into the adjustment layer.
- It may not separate offensive and defensive responsibility cleanly unless the model is designed carefully.

TDNet design rule
-----------------
Adjust per-game contributions first, then roll them into weekly fingerprints. Do not only adjust the already-rolled season-to-date average. Adjusting after aggregation throws away context and makes leakage/debugging harder.

================================================================================
METHOD 2: Joint offense-defense ridge regression / adjusted efficiency models
================================================================================

Common names
------------
- Adjusted offensive/defensive efficiency
- Ridge opponent adjustment
- Regularized offense-defense model
- Team-level adjusted plus-minus style model
- RAPM-style adjustment when regularized

Original / early papers and foundations
---------------------------------------
- David A. Harville (1977), "The Use of Linear-Model Methodology to Rate High School or College Football Teams."
  Early football-specific linear model approach; later offense-defense models are natural extensions.

- Arthur E. Hoerl and Robert W. Kennard (1970), "Ridge Regression: Biased Estimation for Nonorthogonal Problems," Technometrics.
  Original ridge regression foundation. Ridge is crucial when team effects are collinear and early-season schedules are sparse.

- Dan T. Rosenbaum (2004), "Measuring How NBA Players Help Their Teams Win."
  Early detailed public adjusted plus-minus treatment in basketball, controlling for teammates and opponents.

- Joseph Sill (2010), "Improved NBA Adjusted +/- Using Regularization and Out-of-Sample Testing."
  Important RAPM-style paper showing why regularization/ridge improves adjusted plus-minus.

- Brian Macdonald (2011), "A Regression-Based Adjusted Plus-Minus Statistic for NHL Players."
  Clear peer-reviewed regression-based APM implementation that estimates offensive and defensive components independent of teammates and opponents.

- CollegeFootballData blog (2021), "Opponent Adjusted Stats using Ridge Regression."
  Practical college-football implementation note showing ridge regression as a robust way to solve simultaneous offense and defense effects.

Core idea
---------
Instead of saying "Team A gained 0.30 PPA/play," estimate how much Team A's offense contributes after accounting for the defense faced, and how much the opponent defense suppresses or allows.

For a stat where higher means better offense:
    y_game = intercept
             + offense_effect[offense_team]
             + defense_effect[defense_team]
             + home_field
             + error

Possible sign convention:
- offense_effect > 0 means offense raises the stat
- defense_effect < 0 means defense suppresses the stat
or:
- defense_quality > 0 means defense is good, so model as y = offense_effect - defense_quality + home_field

Use one convention and document it aggressively.

Ridge objective:
    minimize sum((y - X beta)^2) + lambda * sum(beta^2)

Why ridge matters
-----------------
College football schedules are sparse and clustered:
- conference teams play each other heavily
- early weeks have limited cross-conference information
- good teams may share many common opponents
- small sample sizes make fixed effects noisy

Ridge shrinks team effects toward zero or toward a prior, reducing variance. This is especially valuable for early-season fingerprints.

Implementation pattern
----------------------
For each stat family and side:
1. Choose y:
       offensive PPA/play
       offensive success rate
       offensive explosive rate
       points/drive
       rushing success rate
       passing success rate
       defensive allowed PPA/play
       defensive success rate allowed
2. Build game rows:
       y = stat by offense team against defense team
       columns = one-hot offense team + one-hot defense team + home/away + optional tempo/garbage-time filters
3. Fit ridge on historical data available before the prediction week.
4. Extract:
       offense_state[team, week, stat]
       defense_state[team, week, stat]
       residual_game_value
       uncertainty_proxy if available
5. Merge into team-week fingerprints.

Important implementation choice
-------------------------------
You can use ridge in two slightly different ways:

A. State extraction:
   Use fitted offense_effect and defense_effect as fingerprint features.
   Example:
       oa2_off_ppa_ridge_state_to_date
       oa2_def_ppa_allowed_ridge_state_to_date

B. Residual extraction:
   Use model residuals as adjusted game contributions, then roll them.
   Example:
       oa2_off_ppa_resid_mean_last_3
       oa2_off_ppa_resid_ewm_to_date

Best TDNet approach:
Use both, but keep them in separate feature families:
- "state" features: the fitted latent offense/defense strengths
- "performance" features: the residualized adjusted game contributions

How to use on fingerprints
--------------------------
For each team-week row:
- Add adjusted offense state features.
- Add adjusted defense state features.
- Add rolling residual features.
- Add uncertainty/sample-size features:
      games_used_in_fit
      opponents_seen_count
      average_opponent_strength
      ridge_lambda
      cross_conf_games_seen
      preseason_prior_weight_remaining
- Preserve v0 raw features for ablation; do not overwrite them.

Best use in TDNet version ladder
--------------------------------
This should be the core of v2:
- v0 = raw/unadjusted rolling fingerprints
- v1 = simple per-game residualized stats
- v2 = joint offense-defense ridge adjusted fingerprints
- v3 = graph/eigenvector/learned schedule graph features
- v4 = temporal/dynamic opponent-adjusted states

Main weaknesses
---------------
- More engineering work than simple residualization.
- Needs careful sign conventions.
- Needs robust validation to avoid leakage.
- Still assumes team strength is mostly static inside the fitting window unless you add recency weights.
- Many stats are correlated; fitting hundreds of separate ridge models can be noisy and expensive unless batched.

TDNet note
----------
This method is the closest classical analogue to what you want TDNet fingerprints to do: transform raw performance into opponent-adjusted offense/defense representations before downstream models see the matchup.

================================================================================
METHOD 3: Paired-comparison win-probability ratings
================================================================================

Common names
------------
- Bradley-Terry model
- Elo rating
- Glicko / dynamic paired comparison model
- Colley Matrix
- Win/loss strength-of-schedule ratings

Original / early papers
-----------------------
- Ralph A. Bradley and Milton E. Terry (1952), "Rank Analysis of Incomplete Block Designs: I. The Method of Paired Comparisons," Biometrika.
  Classic paired-comparison model. If team i and team j are compared, the probability i beats j is modeled as a function of their latent strengths.

- Arpad E. Elo (1960, Chess Life series; 1978 book "The Rating of Chessplayers, Past and Present").
  Elo popularized a sequential rating update for head-to-head outcomes.

- Mark E. Glickman (1999), "Parameter Estimation in Large Dynamic Paired Comparison Experiments," Applied Statistics.
  Technical basis for Glicko; extends paired comparison ratings by incorporating uncertainty/variability in estimates and time-varying ability.

- Wesley N. Colley, "Colley's Bias Free College Football Ranking Method: The Colley Matrix Explained."
  Matrix-based win-loss-only college football ranking method designed to adjust for strength of schedule while avoiding margin of victory.

Core idea
---------
These methods estimate latent team strength from head-to-head outcomes.

Bradley-Terry:
    P(i beats j) = exp(r_i) / (exp(r_i) + exp(r_j))

With home field:
    P(home i beats away j) = logistic(r_i - r_j + H)

Elo:
    expected_score_i = 1 / (1 + 10^(-(r_i - r_j + H)/scale))
    new_rating_i = old_rating_i + K * (actual_score_i - expected_score_i)

Colley:
    Solve a linear system based on wins, losses, and schedule. It is win/loss only and avoids margin of victory.

Implementation pattern
----------------------
For TDNet, build a weekly rating snapshot:
1. Start each season with either:
       all teams equal,
       prior from previous season,
       prior from recruiting/talent/returning production,
       or a blended prior.
2. Before each target week, update ratings using only prior games.
3. Store:
       elo_rating_to_date
       elo_rating_change_last_3
       glicko_rating_to_date
       glicko_uncertainty_to_date
       colley_rating_to_date
       opponent_average_rating_to_date
       strength_of_record_proxy
4. Merge ratings into team-week fingerprints.
5. Also create matchup-level transforms:
       home_rating - away_rating
       rating_sum
       favorite_flag_by_internal_rating
       rating_disagreement_with_model or with Vegas only in eval, not training

How to use on fingerprints
--------------------------
These are best as context features, not replacements for adjusted PPA/success-rate fingerprints.

Good uses:
- Record strength adjustment.
- Strength-of-schedule context.
- "How hard has this team's path been?"
- Priors for early-season ridge adjustments.
- Stabilizing weights for residualization.
- Features for upset prediction and underdog evaluation.

Bad uses:
- Treating Elo alone as opponent-adjusted offensive efficiency.
- Feeding market/Vegas into rating updates if the end-state goal is independent modeling.
- Using final-season ratings to adjust early-season games.

Main weaknesses
---------------
- Outcome-only systems may miss strong teams with unlucky close losses.
- Elo updates depend heavily on K-factor, margin multiplier, home field, and priors.
- Colley intentionally ignores margin, which can be a feature or a limitation.
- These ratings summarize team strength, not unit-level fingerprint structure.
- They can become circular if used carelessly to evaluate the same games that estimated them.

TDNet note
----------
Use paired-comparison ratings as "schedule context" and "team-strength priors." Do not let them replace the stat-level opponent-adjustment layer.

METHOD 4: Eigenvector / graph-centrality schedule adjustment
================================================================================

Common names
------------
- Keener method
- Eigenvector ranking
- Perron-Frobenius ranking
- PageRank-style sports ranking
- Recursive schedule-strength ranking
- Network-based opponent adjustment

Original / early papers
-----------------------
- James P. Keener (1993), "The Perron-Frobenius Theorem and the Ranking of Football Teams," SIAM Review.
  Keener describes methods for ranking teams in uneven paired competition using Perron-Frobenius/eigenvector logic.

- Later PageRank-like sports ranking work generalizes similar graph-centrality thinking: a team is strong if it performs well against teams that are themselves strong.

Core idea
---------
Represent the season as a graph:
- nodes = teams
- edges = games
- edge weights = results, margins, score ratios, PPA differentials, or transformed performance values

Then compute ratings recursively:
- Beating a strong team is worth more than beating a weak team.
- Losing narrowly to a strong team may carry useful information.
- A team's rating depends on the ratings of the teams connected to it.

A simplified version:
    rating = principal_eigenvector(A)

where A is a nonnegative game-result matrix built from pairwise team outcomes.

Implementation pattern
----------------------
For TDNet:
1. At each week w, build a graph from games < w.
2. Choose edge weights:
       win/loss only
       capped margin
       PPA differential
       success-rate differential
       explosive-rate differential
       drive-efficiency differential
3. Compute graph ratings:
       eigenvector centrality
       PageRank
       HITS-style offensive/defensive authority/hub scores
       graph diffusion features
4. Store team-week graph features.
5. Use them as additional fingerprint families.

How to use on fingerprints
--------------------------
Useful v3 feature ideas:
- schedule_graph_strength_to_date
- graph_margin_rating_to_date
- graph_ppa_rating_to_date
- graph_offense_authority_to_date
- graph_defense_authority_to_date
- graph_sos_centrality_to_date
- graph_conference_bridge_score
- graph_uncertainty_proxy based on degree / connectedness

Best role in TDNet
------------------
This method is an excellent bridge from classical opponent adjustment to graph-based TDNet.

It aligns with:
- team nodes
- game edges
- dynamic weekly snapshots
- learned graph embeddings in future v3/v4
- message passing over past games

Main weaknesses
---------------
- Early-season graphs can be disconnected.
- Centrality features can be hard to interpret.
- Many graph methods are ranking tools, not calibrated predictors.
- Edge-weight design can become arbitrary.
- If the graph uses future games, leakage is severe and easy to miss.

TDNet note
----------
Use graph/eigenvector features as a separate feature family. Do not bury them inside the main v1/v2 adjusted stat calculations. This makes ablation cleaner and helps publication framing.

================================================================================
METHOD 5: Dynamic Bayesian / state-space attack-defense models
================================================================================

Common names
------------
- Dynamic paired-comparison model
- Bayesian state-space team-strength model
- Dynamic attack-defense model
- Time-varying rating model
- Kalman-filter-style team ratings
- Dynamic generalized linear model

Original / early papers
-----------------------
- Mark E. Glickman and Hal S. Stern (1998), "A State-Space Model for National Football League Scores," Journal of the American Statistical Association.
  NFL score model with team strengths varying over time, including week-to-week and season-to-season sources of variation.

- Mark E. Glickman (1999), "Parameter Estimation in Large Dynamic Paired Comparison Experiments," Applied Statistics.
  Dynamic paired-comparison model underlying Glicko.

- Mark J. Dixon and Stuart G. Coles (1997), "Modelling Association Football Scores and Inefficiencies in the Football Betting Market," Applied Statistics.
  Soccer score model with attack/defense strengths and dynamic performance complications.

- Havard Rue and Oyvind Salvesen (2000), "Prediction and Retrospective Analysis of Soccer Matches in a League," The Statistician.
  Bayesian dynamic generalized linear model for time-dependent team skills.

Core idea
---------
Teams are not static. Injuries, coaching changes, QB changes, bye weeks, weather, and development all change a team's true strength during a season.

A state-space model separates:
1. latent team state
2. observed game result/stat
3. time evolution

Example:
    offense_strength_team_week = offense_strength_team_previous_week + process_noise
    defense_strength_team_week = defense_strength_team_previous_week + process_noise

Observation model:
    y_game = offense_strength_team_week
             - defense_strength_opponent_week
             + home_field
             + error

For a binary outcome:
    win ~ Bernoulli(logistic(team_strength_i_week - team_strength_j_week + home_field))

For a score count:
    points ~ Poisson(exp(attack_i_week - defense_j_week + home_field))

For football margin:
    margin ~ Normal(team_strength_i_week - team_strength_j_week + home_field, sigma_game)

Implementation pattern
----------------------
Full version:
1. Define latent weekly states for each team:
       offense
       defense
       special teams
       overall
2. Define priors:
       previous season final state
       returning production
       roster talent
       recruiting
       coach continuity
       transfer/QB proxy if available
3. Define observation models for game stats.
4. Fit with Kalman filter, particle filter, variational inference, or MCMC.
5. Snapshot posterior mean and uncertainty before each target game.
6. Merge posterior states into fingerprints.

Practical TDNet approximation:
- Use ridge offense-defense models with recency weights.
- Add prior rows that shrink teams toward preseason priors.
- Decay older games exponentially.
- Carry forward weekly state estimates.
- Store uncertainty proxies based on games played, opponent diversity, and fit variance.

Example recency weighting:
    weight_game = exp(-decay_rate * weeks_since_game)

Example prior blending:
    state_week = prior_weight_week * preseason_prior + (1 - prior_weight_week) * data_fit_state

Why this matters for TDNet
--------------------------
This is the most conceptually aligned method for "time-dependent fingerprints."

It directly supports:
- dynamic season progression
- early-season priors
- uncertainty
- week-by-week leakage control
- rolling team state snapshots
- publication framing around time-aware feature engineering

Main weaknesses
---------------
- More complex to implement and debug.
- Harder to explain than linear residualization.
- Can be computationally expensive for many feature families.
- Requires careful posterior snapshotting to avoid leakage.
- MCMC is probably too heavy for the first implementation.

TDNet note
----------
For publication and engineering, do not jump straight to full Bayesian state-space unless the simpler v1/v2 baselines are already implemented and benchmarked. Use the state-space papers to motivate a staged approximation:
- v1 residualized game contributions
- v2 ridge offense-defense states with recency weights
- v4 dynamic Bayesian or learned temporal graph states

================================================================================
CROSS-METHOD IMPLEMENTATION PLAN FOR TDNet
================================================================================

Recommended version ladder
--------------------------

v0_unadjusted_stats
- Current raw rolling/cumulative fingerprints.
- No opponent adjustment.
- Important as baseline.

v1_residualized_opponent_adjustment
- Method 1.
- Fit leakage-safe linear models per stat.
- Create per-game adjusted residuals.
- Roll residuals into team-week features.
- Best first publishable step.

v2_ridge_offense_defense_adjustment
- Method 2.
- Fit offense-defense ridge models per stat family.
- Extract offense/defense latent states and residuals.
- Add recency weights and priors.
- Best "serious" opponent-adjusted fingerprint generation.

v3_graph_schedule_features
- Method 4.
- Weekly graph snapshots using past games only.
- Add graph centrality/diffusion features.
- Bridge to learned graph embeddings.

v4_dynamic_state_space_or_temporal_graph
- Method 5.
- Time-evolving latent states.
- Posterior means and uncertainty features.
- Strongest academic framing but most engineering-heavy.

Paired-comparison ratings across all versions
---------------------------------------------
Method 3 can be included as a side family in v1/v2/v3:
- internal Elo
- Colley
- Bradley-Terry logistic rating
- Glicko uncertainty
- strength-of-schedule metrics

Keep these separate from adjusted stat families:
- rating_context_*
- schedule_context_*
- record_adjusted_*

Do not mix them into raw stat names.

================================================================================
LEAKAGE-SAFE RULES
================================================================================

Hard rule
---------
For predicting game g in week w:
    every feature must be computed using only games before game g.

If all games in week w are predicted at the start of the week:
    use games through week w - 1 only.

If predicting after some games in week w are completed:
    explicitly define the cutoff timestamp and store it.

Recommended implementation controls
-----------------------------------
1. Build a "fit_cutoff" column for every adjusted feature.
2. Persist game-level adjusted contributions with model_version and cutoff.
3. Unit test that no game_id being predicted appears in its own adjustment fit.
4. Unit test that no future opponent games are included.
5. Avoid final-season opponent ratings for in-season features.
6. Do not use Vegas/market data in training features if the model goal is independence.
7. Do not use CFBD opponent-adjusted metrics as inputs to your own opponent-adjustment models unless explicitly labeling them as external adjusted features.
8. Compare held-out seasons only; do not tune adjustment hyperparameters on the same seasons used for final evaluation.

Early-season handling
---------------------
Weeks 1-3 are sparse. Options:
- no opponent-adjusted feature until enough games exist
- blend with priors
- use previous-season priors
- use recruiting/talent/returning-production priors
- fit across multiple seasons with season effects
- use ridge shrinkage
- use confidence/uncertainty columns so downstream models know the feature is low-information

Recommended TDNet early-season approach:
- v1: residuals only after a minimum sample threshold; otherwise fallback to raw + prior/SOS context.
- v2: ridge with prior rows and recency weights.
- v4: posterior uncertainty directly.

Team-week fingerprint additions
-------------------------------
For each adjusted stat:
- adjusted_mean_to_date
- adjusted_mean_last_3
- adjusted_ewm_to_date

- adjusted_best_game_to_date

Matchup-level transforms
------------------------
After building home and away fingerprints:
- home_adjusted_feature - away_adjusted_feature
- home_adjusted_feature + away_adjusted_feature
- abs(home_adjusted_feature - away_adjusted_feature)
- home_offense_state - away_defense_state
- away_offense_state - home_defense_state
- interaction: home_offense_strength * away_defense_weakness
- schedule_context_difference
- uncertainty_difference

Evaluation targets
------------------
Evaluate v0 vs v1 vs v2 using:
- margin RMSE / MAE
- winner accuracy
- favorite accuracy
- underdog accuracy
- upset recall
- rank upset recall
- record upset recall
- edge_3_plus_accuracy
- calibration of predicted win probabilities
- performance by week bucket:
      weeks 1-3
      weeks 4-7
      weeks 8-12
      postseason/bowls
- performance by conference / cross-conference
- performance by favorite size
- performance on model-vs-Vegas disagreement games, with Vegas only in eval

SHAP / feature diagnostics
--------------------------
For each model family and fingerprint version:
- SHAP global importance by feature family
- SHAP importance by week bucket
- SHAP dependence plots for adjusted vs raw stats
- permutation importance by feature family
- ablation:
      raw only
      adjusted only
      raw + adjusted
      adjusted + schedule context
      adjusted + priors
- leakage/suspicion audit:
      features with sudden unrealistic importance
      features whose importance is strongest in current-week-only columns
      features with too much direct label correlation

================================================================================
PRACTICAL RECOMMENDATION
================================================================================

Best immediate next step
------------------------
Implement v1 with Method 1:
- Pick 5-10 core stats.
- Build per-game residualized adjusted contributions.
- Roll them into team-week features.
- Compare v0 vs v1 across TDLinear, TDTree, and TDStat.
- Plot margin parity, winner accuracy, upset recall, and edge_3_plus_accuracy.
- Use SHAP/permutation to decide which adjusted features are worth keeping.

Then implement v2 with Method 2:
- Joint offense-defense ridge.
- Add priors and recency weights.
- Keep raw, residual, and latent-state features separate.

Most publishable research framing
---------------------------------
A strong academic contribution is not "I made another rating system."
A stronger framing is:

"How much do leakage-safe opponent-adjusted and time-dependent fingerprint representations improve college football prediction across model families, target types, and season stages?"

This lets TDNet contribute a feature-engineering benchmark:
- raw fingerprints
- residualized opponent-adjusted fingerprints
- ridge offense-defense fingerprints
- graph schedule fingerprints
- dynamic time-dependent fingerprints

The gap is especially interesting if you evaluate multiple targets:
- winner
- margin
- upset recall
- favorite correctness
- season win total as season progresses
- model-vs-market disagreement evaluation, with market held out of training
